# Phase 1.5 - Mbox Completion

Focus: Mail without the noise: clean an mbox of junk, sort it by sender, import only the conversations that matter, summarize each one locally, and keep what is left in a smaller mbox

Verify command (the suites every ticket's last task ran; the Requirements name no single one):
**`python -m pytest -q && (cd tools/chattr && python -m pytest -q) && (cd web && pnpm exec tsc --noEmit && pnpm exec vitest run)`**
Last run 2026-11-24: Caixa 1532 passed, 1 skipped, 1 deselected (the slow scale test); Chattr 912
passed; web: types clean, 277 passed. `mypy` stops on a numpy stub in this environment (not this
project's code), and keeps four older notes in `caixa/apple_intelligence.py`, `translation.py` and
`summaries.py`.

## At a glance

46 tickets, all done (2026-11-20 to 2026-11-23). The 15 planned tickets built the mail workflow:
read an mbox once into an index (workers), clean it of junk with a receipts guard and write a
Cleaned copy, sort senders and import only the chosen conversations, draw each conversation as one
page of cards filed with its person, summarize conversations on this computer, and write a Reduced
mbox of what was left out. 31 hot fixes followed the maintainer's own testing on real mail:
Apple Intelligence as the first choice for summaries and translation, subcategories and selection
on the people page, merging and deleting people by dragging, mail by account and folder, robustness
for real mbox files (undecodable characters, attachment races), and finally the redraw itself:
12.8 s down to about 2 s on a 3,000-mail synthetic box, pages shared among workers, only changed
pages rewritten, and changes batched behind one **Update the pages**. The project branch is
`2026-Istanbul/Phase1.5-Mbox`; released as **v0.5.1**, merged into `working`, then `main`, on 2026-11-24.

## Testing guide for human testers

Run the verify command above first and confirm it passes, then walk through each ticket below by
hand.

**Setting up.** Use a new box (`caixa serve`, then make a box with an owner) so nothing real is at
stake. The synthetic noisy mailbox is the safest first source. Run from `tools/chattr/tests`:

```bash
python -c "from pathlib import Path; from fixtures.builders.noisy_mbox import build_noisy_mbox; print(build_noisy_mbox(Path('/tmp/noisy')).gmail)"
```

It prints the path of a Gmail-shaped mbox (56 mails) holding every case the tickets name. Then try a
small mbox of your own and follow `docs/Documentation/Collector.md` (Mail → *Your first own mbox*).
Never commit an mbox or anything drawn from one.

**The main workflow (tickets 01–15).** Import → Mail opens Clean mail: read the mbox (name the
account), look through the junk groups and Receipts, Keep a sender, write the Cleaned mbox (or Skip
cleaning). Open Sort mail on it: check Known, choose and ignore senders, confirm your addresses,
import, and read the report at the end. Open a person's page: the calendar at the top, the mail
entries, Read the conversation, the cards, files and All headers. Open the people page → Mail ▸
account ▸ folder. Turn on summaries (Apple Intelligence on a Mac that has it, or a local model),
Summarize mail now, read them. Write the reduced mbox and read it again.

**The people page (hot fixes).** Unfold a category, add a subcategory and one under it, rename it
with a double click, ⌘-click a label to flatten it. Select with ⌘-click, Shift-⌘-click and a box;
drag people onto categories from any view. Drop one person, or several, onto another, named or in
Unrecognized: one person is left with the name of the one dropped on. Delete someone met in mail:
no tile comes back, and their mail stays under `People/Removed/Mail/<Account>/`. After each change
the blue bar counts the changes not yet on the pages; **Update the pages** draws them (the yellow
bar locks the page while it runs). Sorting alone redraws the people page only.

**Real mail.** Import a folder holding a received and a sent mbox of one account: both are listed
under "Mboxes already read"; your replies join the conversations they answer. A large mbox should
import whatever its characters (a stray Latin-1 "ñ" is kept as "ñ"), and with several workers.

**Redraws.** Watch the terminal during **Update the pages**: each step ends with what it did, the
workers used and the time it took. Settings → Performance → Workers changes how many processes
write the pages.

**Apple Intelligence (only a Mac can do this).** On macOS 26 or later with Apple Intelligence on:

```bash
xcrun swift build -c release --package-path tools/apple-intelligence
```

```bash
tools/apple-intelligence/.build/release/caixa-apple-intelligence --check
```

It should print `{"ready":true}`. Settings → Summaries and → Translation use it first (Automatic).
`caixa benchmark` compares it with a local model (`tools/ai-benchmark/README.md`).
