## Description

After an import, write the Reduced mbox: every mail of the sorted mbox that was not imported,
ignored senders included.

## Acceptance criteria

- [ ] A finish step, after an import has finished, writes `(YYYY-MM-DD) <name> [Reduced].mbox` with the mbox writer
- [ ] It holds exactly the mails not imported (checked mail by mail), ignored senders' mail included
- [ ] Reading it again shows the imported senders under Imported and the ignored under Ignored
- [ ] The finish dialog says that undoing the import afterwards leaves those mails only in the source
- [ ] `caixa mail reduce`

## Implementation plan

Status: done
Current task: 

**Design:** a mail of the sorted mbox is **imported** when an import took it (the import job records
the positions it took in the index's new `imported` table, schema 4) or when its Message-ID is in the
box's mail already. `mail.reduce` (a `mail-reduce` job) writes `(date) <name> [Reduced].mbox` with
every other mail, ignored senders' included, with ticket 04's writer (checked mail by mail, the
source unchanged, recorded as the source's `reduced` child). Reading the Reduced mbox again: the
ignored are Ignored (their mail is still in it, and `owner.json` remembers them); the senders whose
mail was all imported have no mail left in it, so they are listed under Imported from the mboxes it
came from (no mails of their own here). In Sort mail, the Imported notice offers **Write the reduced
mbox**, which asks first (how many mails stay, where the file goes, that the source is not changed,
and that undoing the import afterwards leaves those mails only in the source), follows the job and
links to sorting the Reduced mbox. `caixa mail reduce PATH`.
